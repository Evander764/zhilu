# 知路：从探索到阅读，再到讨论

2026-09-08。B 方向的桌面交互候选。本轮实现：紧凑卡片、悬停/键盘聚焦预览、相关边高亮、点击阅读、引用原话进入讨论草稿。多人讨论尚未接入；界面明确显示“讨论预览 · 尚未联网”。手机按用户要求暂缓。

## 交互模式

| 动作 | 用户得到什么 | 状态变化 |
| --- | --- | --- |
| 鼠标触碰卡片 / 键盘聚焦 | 140ms 边框和阴影反馈，相邻连线加深；停留 180ms 出现一段原话、作者、内容数量 | 不改当前问题、不改轨迹、不请求全文、不移动画布 |
| 移开 / Esc / 拖动画布 | 预览收起，关系线恢复 | 没有写入 |
| 单击 / Enter | 固定当前问题，右侧阅读打开，地图显示当前问题及相邻关系 | 写入本机阅读轨迹；原话和阅读标题同步 |
| 阅读原文 | 在新标签打开该回答或文章的确切链接 | 知路仍停在原节点，回来继续读 |
| 引用讨论 | 同一问题的讨论页打开，携带所点来源的原话与作者 | 引用锚点为 sourceId，文字从现有来源读取；草稿按问题隔离 |
| 阅读 / 讨论切换 | 同一上下文内切换，无全屏跳转 | 保留阅读位置和本机草稿 |

视觉密度：卡片由约 273×194 显示像素缩为 208×137（1440×1000 默认全图），面积约减少 46%。宽度由 248px 改为 208px，默认缩放不超过 1；不能让自动 fitView 把缩小后的卡片重新放大。长标题在地图最多三行，完整标题进入阅读后可查。搜索与卡片去掉重复平台名称，来源元信息保留“回答 · 知乎”，不会去除作者或原链接。

## 与原站内容的边界

现有代码取得的是搜索片段与作者/链接，不是全文。站内先显示原话、导读、来源范围；全文用原始 URL 打开，不把网站嵌入 iframe，不制造“已拿到全文”的假象。原站的点赞、收藏、评论在原站本人账号下完成。

已在本轮运行知乎 CLI 0.5.0 的 capabilities；清单包含搜索、直答、本人创作/关注/收藏读取、知识库和额度，没有评论读取/发布、点赞或收藏写入命令。这个结论只覆盖当前公开接入能力，不声称平台永远不支持。知乎官方入口：https://developer.zhihu.com/ 。不使用逆向接口或共享账号代发评论。

## 实时讨论第一版

建议每个问题一个房间；引用回答是房间内的话题锚点，避免讨论散到一个全站大群。用户可以“追问”或“补充经验”，回复挂在具体发言下。一条讨论可以回看它引用的来源，但讨论热度不会把编辑关系升级为已核对的事实。

访客可阅读。首次发送时完成项目身份登录；身份由服务器的会话取得，不接受客户端提交 authorId，不把站内昵称当知乎账号。当前应用公开匿名模式还没有讨论表、讨论接口、发言身份或推送入口，登录与平台运行环境都需要联调验证。

传输选择：普通 HTTPS POST 发送；消息持久化成功后，通过 SSE 向订阅该问题的人推送。NestJS 已在项目中，官方支持 @Sse 和 EventSource。文字讨论暂不需要双向光标或连续输入状态，因此第一版无需 WebSocket。方案依据：https://docs.nestjs.com/techniques/server-sent-events 。部署代理是否缓冲、连接超时、平台身份透传尚未验证；必须经过真实部署的流式探测，不把本地 Nest 支持当作妙搭线上已支持。

建议契约：

- GET /api/zhilu/discussions/:questionId/messages?after=cursor：按房间序号增量读取，可分页。
- POST /api/zhilu/discussions/:questionId/messages：body、kind、sourceId?、parentId?、clientMessageId；作者由服务端身份派生。
- GET /api/zhilu/discussions/:questionId/events：SSE；事件至少含 eventId、roomId、messageId、revision、type。type 区分新增、编辑、删除。
- 服务端检查问题存在、引用属于此问题、父消息属于此房间；长度上限、速率限制、CSRF、删除和举报入口一并实现。

存储：discussion_rooms、discussion_messages、discussion_events。客户端临时发送 UUID 与会话身份构成幂等键；消息、房间有序序号、事件 outbox 在同一事务提交后才发“成功”。多实例使用共享事件分发，数据库事件是恢复真源；不能只依赖单实例内存 Subject 或 Redis Pub/Sub 保存消息。

接收状态：在底部读最新消息时自动追加；正在读历史时只显示“有新回复”，用户点后再滚到底。发送中、失败可重试、重连中要可见。掉线重连携带最后处理的事件 ID，服务端补发遗漏并按 messageId/revision 去重。事件保留期之外用房间快照加游标重建。切换问题时取消旧订阅，并丢弃旧请求迟到结果。删除事件同步移除正文。草稿独立于公共分享链接，不发布前不传给其他人。

在线人数与“正在输入”放到后续；第一版不显示占位人数。房间链接支持直达“讨论”页和某条发言，复制路径仍只包含公开路径。平台不支持稳定流式响应时先用增量短轮询，界面如实显示刷新中；不能把它宣称为已验证的实时推送。

上线验收必须有：两个独立浏览器会话互发并实时收到；刷新后消息仍在；断网重连不丢不重；房间隔离；无权限发言被拒；引用跨问题被拒；后台删除同步；长时间连接经过真实平台不缓冲；分享不带私有草稿。目前这些都未运行，不能称为实时讨论已上线。
