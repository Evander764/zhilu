## 授权流程

用户先登录本应用，点击“连接知乎”，在知乎确认授权，然后返回账号设置。浏览器携带授权码调用后端；后端换取 OAuth token，并从创作、关注、收藏夹、收藏夹内容、近期收藏各读取最多 1 条，返回有限的标题、摘要、知乎原文链接和读取状态。空列表与请求失败分别展示；没有收藏夹时跳过依赖请求。

这是按 Hackathon Skill 提供的首次授权联调能力。Token 只存在于一次后端请求的内存中，不进入数据库、cookie、浏览器或源码。结果只在当前页面内存中展示，刷新页面需要重新连接；目前没有持久绑定、后台同步、刷新 token 或远端撤销功能。

回调先进入本应用的前端路由，再通过平台 `axiosForBackend` 调用后端，保留妙搭原有 CSRF 防护和登录上下文。授权码不写入 web storage；浏览器在发起请求前移除地址栏中的回调查询参数，页面设置 `no-referrer`。

请求关联校验使用短期签名 state、当前妙搭用户以及浏览器独有随机证明。用户标识不以明文放入授权链接。不同实例之间不依赖进程会话；授权码由知乎单次兑换，浏览器在回调时消耗待处理证明。平台回调不返回 state、state 不符、过期、换账号、证明缺失时均停止兑换，不降级为开发者身份，不建立连接。

官方 OAuth 资料记载过“不返回 state”的协议缺口。如果实际仍如此，页面会明确说明该回调仅适合临时联调并停止本次连接，需要向知乎确认协议支持。

## 配置与启用条件

线上后端使用以下独立变量；不复用旧搜索服务的 `ZHIHU_ACCESS_SECRET`，避免顺带启用旧搜索功能：

- `ZHIHU_OAUTH_APP_ID`
- `ZHIHU_OAUTH_APP_KEY`
- `ZHIHU_OAUTH_ACCESS_SECRET`
- `ZHIHU_OAUTH_REDIRECT_URI`

初始配置的登记确认变量缺省，入口显示等待登记。**只有取得 App 661 管理方对上方完整妙搭回调地址的登记确认后**，才把 `ZHIHU_OAUTH_REGISTERED_REDIRECT_URI` 配置为该完整地址并重新发布。其他域名的登记确认不会生效。不得把 127.0.0.1、Vercel 的地址或未经确认的地址当成本应用已登记事实。

App Key 来自初始化项目的 macOS 钥匙串，Access Secret 来自官方 CLI 钥匙串；通过标准输入配置到本应用的 online 环境，不进入命令参数或 Git。专用 `HttpModule.register` 创建独立 HTTP 客户端，避开平台通用请求日志；第三方错误只转成固定文案，不携带请求配置、凭证或原始响应。
